## Defects found and fixed during integration

1. Goong V1 Directions ignored the unsupported `waypoints` query parameter, initially making
   candidate routes identical to the direct route. Waypoints are now serialized as intermediate
   semicolon-separated destinations and covered by a regression test.
2. INFO-level `httpx` logging can include the Goong key in its full request URL. Third-party HTTP
   client logs are now suppressed below WARNING; application integration logs never log queries.

## Security follow-up

One local diagnostic command emitted a full Goong request URL before `httpx` log suppression was
added. The key is not present in repository files or browser traffic, but it appeared in the task
console history. Rotate the Goong REST key after this session and update the ignored root `.env`.

## Remaining limitations

1. The Phase 04 occupancy model is not available. Forecasting remains persistence-based and the
   UI reports that state explicitly; therefore the release gate is blocked.
2. Arbitrary locations require Goong or OSRM routing. Only fixed demo scenarios have offline route
   caches; an uncached journey returns a clear 503 if both providers fail.
3. Runtime event and planned-arrival state remain in-memory and reset on backend restart.
4. Deterministic browser automation for every event scenario belongs to Phase 10. Phase 09 has
   component/API tests plus a live end-to-end browser smoke test.
5. The map SDK remains the dominant production bundle and should be code-split before release.
